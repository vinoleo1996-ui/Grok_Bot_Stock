## 0. 方法论声明
这个设计是在看过 MA-RP、X-D、SC-* 的密封窗结果之后提出的，属于事后设计。所以只按两个探索窗（2015-06→2017-12，2024-06→2026-10-09）加 2026-11 起的前向模拟盘判定，密封窗（2018-01→2024-05）只跑一次，**只作描述**。对照：SC-VT20（同样是探索窗 + 密封窗描述）。

## 1. 机制（钱从哪里来）
- 债券腿（T 十年、TF 五年国债期货）：收期限溢价。期货多头的收益 ≈ 现券持有收益（票息 + 骑乘）− 融资成本（隐含回购利率），再加上基差收敛。用期货代替现券或 ETF，可以低成本加杠杆，保证金只占 1–2%。
- 股票腿（IF、IC，不用 IM）：收股权溢价，加上对冲需求补偿（IC 贴水，见 V3_B2）。
- 黄金腿（518880 现货 ETF，中金所没有黄金期货）：央行购金、实际利率、避险需求，与股债低相关。
- 风险平价：三条腿风险相等，再用期货的内嵌杠杆把组合波动拉到 14%。不需要融资账户：期货只占保证金，现金放在 511880 收货币利率。这对 SC-VT 的改进在于：(a) 股票腿多收 IC 贴水；(b) 债券腿不付 Shibor+1% 的融资利差，杠杆成本只有期货内含的回购利率；(c) 不受 2× 融资杠杆上限的限制。

## 2. 数学
- 腿内部固定等权：债券腿 = 50% T + 50% TF（按名义）；股票腿 = 50% IF + 50% IC（名义）；黄金腿 = 518880。
- 腿的日收益代理：期货腿用主力连续合约（季月、按下面的规则展期）结算价收益的名义加权；黄金用 518880 后复权收益。
- 风险预算权重：w_k ∝ 1/σ_k，σ_k = 过去 60 个交易日的日收益标准差，Σw_k = 1（等风险贡献的对角近似）。
- 组合杠杆：L = min(14% / σ̂_p, L_cap)，σ̂_p = 用当月 w 合成的腿代理收益的 60 日年化波动。
- 名义：notional_k = w_k · L · NAV（腿内再按 50/50 拆）。期货手数 = round(notional / (结算价 × 乘数))；乘数 IF 300、IC 200、T/TF 10000。
- 保证金约束（决定 L_cap，事先固定）：期货保证金占用 M = Σ |notional_j| · m_j（m：IF/IC 按 futures.MARGIN_TABLE 的日期表，T 2%、TF 1%，按 BOND_MARGIN_TABLE），黄金占用 G = w_g·L·NAV（现货全额）。要求 **M + G ≤ 0.80 × NAV**，即留出至少 20% NAV 的现金作为盯市缓冲。L_cap 每月按当月 w 和保证金率解出：L_cap = 0.80 / (Σ_k w_k·m̄_k + w_g)，m̄_k 为腿内平均保证金率；另设硬上限 **L ≤ 6.0**（防止债券低波时名义失控）。
- 现金：NAV − M − G 全部按 511880 后复权日收益计息（ExecConfig.cash_rate，return 型）。
- 调仓：每月最后一个交易日出信号，下一交易日开盘成交。
- **展期**：国债期货的个人或一般账户不能进入交割月，交割月的保证金也会上调，所以**所有期货腿统一在合约最后交易日前 15 个交易日展期**（国债期货的最后交易日是交割月第二个周五，15 个交易日 ≈ 交割月开始之前；股指期货也用同一规则，便于统一实现）。只用季月合约。
- 成本：股指按 futures.FEE_TABLE（日期表），国债期货按 BOND_FEE_TABLE（3 元/手开仓和平昨，平今免），每边 1 跳滑点（股指 0.2 点，T/TF 0.005 元）。518880 按引擎默认 ETF 成本。
- 收益分解（报告必须给出）：组合收益 = Σ 腿内"现货指数或现券的近似收益" + 基差收敛 + 现金利息 − 成本。股指腿：基差收敛 = 期货收益 − 指数收益（IC 贴水，同 B2）。国债腿：基差和隐含回购收益需要 CTD 现券价格和转换因子，**box 上没有**，所以只报告"期货展期收益 = 新旧合约价差"和总收益，隐含回购分解标为待数据。

## 3. 可证伪的预测（运行前写下）
1. 实现波动接近 14%（偏差 ≤ ±3pp），因为在 0.80 保证金约束下 L_cap 通常 > 14% 目标所需的 L，**上限一般不卡住**（与 SC-VT20 被 2× 卡住、只做到 8–9% 波动不同）。
2. 夏普接近 MA-RP 同窗（差距在 ±0.3 以内），因为本质上是同一个风险平价，只是杠杆更高、成本结构不同；X1 夏普的符号与 MA-RP 相同（MA-RP X1 = 0.70 > 0）。
3. 最大回撤 ≤ 25%（两个探索窗都满足）。
4. X2 年化 ≥ 12%。
5. 相对 SC-VT20：X1 夏普更高（没有 CB 降级袖套，也没有融资利差）。

## 4. 失效条件（逐项报告）
- 2020-03 流动性冲击：股债金同时下跌，杠杆放大损失（在密封窗里，只描述）。
- 2022-11 股债双杀：国债期货急跌，债券腿高杠杆受伤（密封窗，只描述）。
- 2016-12→2017 债市下跌（X1）：T/TF 连续下跌，债券腿名义最大，预计是 X1 最大的回撤来源。
- 保证金不足或强平：统计 fut_margin_shortfall 事件数；任何一次 shortfall 都要报告日期和原因。
- 基差急剧变化：IC 贴水收窄（2024-01/02），国债期货基差扩大；报告单日基差变化最大的 5 天。
- 合约流动性：TF 2013–2015、T 2015 年早期成交稀少，用参与率上限检查成交率。

## 7. 阻塞项
1. **展期规则（Eng）**：§2 要求在交割月之前展期（最后交易日前 15 个交易日）。FuturesConfig.roll_days 是整条腿共用的参数，需要确认 roll_days=15 对 T/TF/IF/IC 混合持仓都正确，并且 load_index_futures_panels 的合约文件匹配模式（根代码 + 4 位数字）对 "T" 不会误配 TF、TS、TL（"T[0-9][0-9][0-9][0-9]" 不会匹配 "TF1312"，但需要 Eng 确认 root_of / 季月判断对 T、TF 正确）。
2. **国债期货保证金历史（Data / Eng）**：BOND_MARGIN_TABLE 只有一个常数，2015–2017 期间交易所的实际保证金和调整记录需要核实（影响保证金约束和 L_cap）。
3. **CTD 和隐含回购（Data，可选）**：要做债券腿的 carry 分解，需要 T/TF 的可交割券清单、转换因子和现券日价格。没有这些也能运行，只是分解不完整。
4. **股指 + 国债同一个 FuturesLeg 的混合持仓**：需要 Eng 确认 FuturesBook 能同时持有多个根代码（IF、IC、T、TF），各自独立展期、各自的费率和保证金。
