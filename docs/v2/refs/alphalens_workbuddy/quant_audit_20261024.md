**这套模型目前没有可验证的稳定 alpha。它可以当"筛选和解释工具",不能当"照着买"的策略。**

## 2. 最严重的问题:回测证明不了实盘

### 2.1 原来是什么样

| | 实盘 `engine.build_universe` | 旧回测 `backtest2._simulate` |
|---|---|---|
| 因子 | 8 维(趋势/动量/量价/资金/板块/反拥挤/反转/低波) | 3 项(60 日动量 50% + 20 日动量 28% + 反拥挤 22%) |
| 权重 | 随市场状态切换(5 档) | 固定 |
| 拥挤度 | 位置 32% + 超额分位 52% + 乖离 10% + 放量 6% | 位置 50% + 涨幅 50%(**没有相对大盘超额**) |
| 闸门 | 拥挤闸门 + 避险拥挤规则 + 新建仓预算 | 无 |

结论:那份"+7 个百分点超额"只证明了一个三因子动量模型在 2022–2026 能跑赢,和你在页面上看到的信号没有关系。

### 2.2 统一之后

回测现在用同一套:同一个 `WEIGHTS`、同一个拥挤度公式、同一个拥挤闸门、同一个状态识别(3 日平滑)、同一个目标仓位。

结果(2022-01 ~ 2026-10,35 只行业+宽基 ETF,单边成本 0.13%):

```
全样本:     +7.28%   年化 1.55%   Sharpe 0.19   最大回撤 -23.3%   429 笔   胜率 39.6%   盈亏比 2.09
样本外拼接: -15.95%  vs 沪深300 -6.37%   →  超额 -9.58pp
9 个窗口:   4 个正收益,4 个跑赢基准
IS Sharpe 0.41  →  OOS Sharpe -0.64   (衰减 -1.05)
```

### 2.3 敏感性检验:结果对执行细节极度敏感

固定打分,只改三个执行参数(持仓数 3-6 / 调仓周期 10 或 21 日 / 状态变化是否立即调仓),共 24 组:

```
收益中位数 +17.4%   最好 +31.8%   最差 -7.5%   标准差 13.0pp
正收益 19/24;24 组全部跑赢基准(基准 -11.14%)
按"状态触发调仓"开关分组:
  any   : 中位 +25.3%  区间 [+1.9%, +31.8%]   (但交易 892-1002 笔)
  worse : 中位 +12.3%  区间 [-7.5%, +23.2%]
  none  : 中位  +8.8%  区间 [-6.2%, +30.9%]
```

**怎么读这组数**:全样本里 24 个配置全部跑赢基准,说明"选强不选弱 + 拥挤闸门 + 状态降仓"这套框架方向没错;
但**同一框架下收益能从 -7.5% 摆到 +31.8%**,说明具体能赚多少取决于运气和执行细节,不是一个稳定的数。
再叠加 walk-forward 的 -16%,更保守的结论是:**框架有相对优势,绝对收益不可预测。**

## 3. 其余问题的细节

### 3.1 标的池污染(P0)

```python
# 修复前:bars 里有什么就打什么分
for sid, b in bars.items():          # 含 1.000300 指数 + 35 只 ETF + 327 只股票
    f = factors(b, bench_cl)
```
后果:
- ETF 会进 TOP20(实测"银行ETF华宝"评分 0.64、"电力ETF广发"0.60)
- 广度、分位、拥挤度全被 ETF 稀释
- `paper.jsonl` 记录了 4 只 ETF,纸面账本从第一天就是脏的

已改为显式传入 `universe`(仅股票),并清空重建了账本。

### 3.2 仓位自相矛盾(P1)

`position_pct` 是"单票风险预算上限"(单笔风险 1% ÷ 止损距离),它本来就不该相加。
但页面上直接列出 20 个 8%~20%,读者自然会加,一加就是 395%。

已改为:按建议总仓位等比压缩成**组合权重**,并保留 `position_cap` 作为单票上限参考。
现在 TOP10 之和 = 建议总仓位(30%)。注意副作用:防守状态下单票只有 2-3%,看起来"很小",这是对的。

### 3.3 状态机抖动(P1)

`detect_regime` 用当天分数直接分档,在阈值附近来回跳。实测 38 个采样点翻 16 次 ——
意味着目标仓位在 15%~80% 之间反复,实盘会被交易成本磨死。

已改为对最近 3 个交易日的分数取均值再分档(`smooth=3`),并把"阴跌缩量"从 crisis 降级为 defense。

### 3.4 止损被抬到 MA60 上方(P2)

```python
if ma60 and ma60 < price and ma60 > stop:
    stop = max(stop, ma60 - 0.5 * atr)    # ← 把止损抬到 MA60 附近
```
本意是"回踩不破 MA60 就持有",实际效果是"碰到 MA60 就跑",与策略叙事相反。已改为取结构位与 2.5ATR 中更宽的一个。

### 3.5 退出条件过敏(P1)

单日收盘跌破 MA60×0.995 且持有 ≥3 天就清仓。ETF 在 MA60 附近震荡极频繁,
结果 727 笔交易里 590 笔是"排名退出"、平均持有 5 天,摩擦成本吃掉大半收益。

已改为:连续 2 日收在 MA60 下方 1% 以上,并且 MA20 也已失守,才认定趋势破坏。

### 3.6 中美混算(P1)

`up_ratio` 把美股上一交易日的涨跌和 A 股盘中的涨跌放在同一个分母里。
已改为广度只统计 A 股(292 只),美股/港股仍参与个股排序但不影响状态判断。

### 3.7 基准口径(P3,已核对无大碍)

担心"用价格指数当基准,把 ETF 分红算成超额"。实测:
沪深300 指数 -22.07% vs 沪深300ETF -21.67%,差 0.40pp,不构成实质虚增。

## 4. 仍然存在的问题(没修,也不打算假装修好)

1. **单一市场、单一样本**:只有 2022–2026 一段 A 股,跨市场/跨周期的验证不足。
2. **ETF 代理粗糙**:30 只 ETF 代表 30 个行业,申万二级(城商行 vs 国有大行)区分不了。
3. **拥挤闸门阈值是手设先验**(0.68~0.82),没有统计最优解;换成别的阈值结果会变。
4. **纸面账本太短**:从今天开始记,至少 2-3 个月才有统计意义。
5. **不建模**:涨跌停无法成交、ETF 折溢价、大额冲击成本、分红再投资、T+1 申赎。
6. **美股没有主力资金口径**,资金因子恒为中性 0.5,等于美股少了一个维度。
7. **walk-forward 的参数选择用训练段 Sharpe**,252 天里只有 3-6 笔交易,这个选择本身噪声极大。

## 5. 这套系统该怎么用(审计后的建议)

**可以信的部分**
- 行情/K线/资金流/ETF 全景的数据准确性(有降级链和新鲜度标注)
- 单标的多指标研判的**指标计算**(MA/MACD/KDJ/BOLL/ATR/ADX/OBV/筹码峰都是标准公式)
- "不追拥挤板块""不在暴跌当天割""分批止盈"这些**纪律**,它们降低的是尾部风险,不是提高收益
- 板块拥挤度的**相对排序**(谁被买过头了),这个从数据上看是有效的

**不能信的部分**
- 任何"预期收益""年化 X%"的暗示
- TOP20 的排序当作买入优先级
- 回测数字当作未来收益的估计

**如果要用真钱**
1. 先让纸面账本跑满 2-3 个月,看"平均超额"是否持续为正
2. 单笔风险不超过总资金 1%,单板块不超过 12%
3. 只做系统里"建仓 + 拥挤度 < 0.6 + 板块不拥挤"的交集,其他一律不碰
4. 止损必须无条件执行 —— 这是整套模型里唯一确定有效的东西
