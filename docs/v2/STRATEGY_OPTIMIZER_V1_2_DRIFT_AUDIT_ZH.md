## 根因（结论）
**整手实现缺陷**，不是求解器问题，不是 wb 不一致，也不是数据缺口。`lot_round_greedy`（research/optimizer_core_v1_1.py）先把每只票向下取整到整手：一手金额大于目标金额的高价股会被**清零**；随后的贪心补手只检查单票上限和行业，**不检查 Size/MidCap/β**。被清零的多是高价、高 β 的大盘股，所以漂移系统性偏向**低 β、偏离中盘**。2025-07 以后这些股价格大幅上涨，问题更集中。

## (1) 整手前 w_opt 是否越界（求解器同口径）
- 抽样 2024-03-29、2025-07-31、2026-08-31、2026-10-09，以及 Arch 复算 2026-01 至 2026-10 的全部 OK 日：整手前**全部在界内**，约束经常**刚好贴边**（β = ±0.100、MidCap = −0.400 = −0.35−0.05 slack）。
- 例：100万 2026-07-31，整手前 MidCap −0.400，整手后 −0.934；60万 2026-08-31，整手前 β −0.100，整手后 −0.336。

## (2) wb 同源性
- 求解器的 wb 与 C1 复核的 wb 是**同一个对象**：`C.prepare_day(d)["wb"]`，调仓日 float_mktcap 快照，池内归一。复核是在同一 run 内对同一个 D 计算的，差异为 0。
- Eng `bench_hiliq_wb_x2.csv` 只有 date/ret/n，是收益序列，**没有权重，无法逐日做权重差**。同源（同一 mask + float_mktcap）但成分数量不同：bench 每日 t−1 加权，in_universe 做了 ffill(limit=5)；求解器池要求收益历史 ≥40 天。示例：2026-08-31 bench 3111 只，求解器 3022 只（与 Arch P2-1 一致）。**这不是漂移根因**，IR_vs_wb 只能近似参考。
- 附注：β 已按全池 wb 加权，但 β_b 在所有日期都等于 1.01695（=60/59）。这是 β 估计的自由度口径造成的常数，不影响约束一致性。
