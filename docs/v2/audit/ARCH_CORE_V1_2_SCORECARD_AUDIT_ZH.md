## 结论
- 求解器**没有失守**：β、MidCap、Size 都在约束里（research/optimizer_core_v1_1.py:50-52，β 框 ±0.10），v1.2 运行时 POOL_STD 和 BETA_POOL 都是 True（research/optimizer_core_x2_run.py:202），slack 有上限：Size 0.05σ、行业 1pp（optimizer_core_v1_1.py:69-70；optimizer_lambda_calib_sealed.py:70-71）。复算 2025-06 到 2026-10 的可行日，整手前 w_opt 的 |β|≤0.100，|MidCap|≤0.40（=0.35+0.05 slack），全部在界内。
- 大幅负向漂移**来自整手这一步**：`lot_round_greedy`（optimizer_core_v1_1.py:86-118）。一手的金额超过「单票上限×AUM」的高价股会被向下取整到 0 手，腾出的权重再贪心补给其余持仓，这一步完全不检查风格。被清零的票：300750、300308、688256、300476、688008（高 β、大市值）。从 2025-09 起逐月出现，被清零的权重 60万 2–15.5%、100万 3–8.6%。典型日：
  - 60万 2026-08-31：整手前 β −0.100、MidCap +0.268；整手后 β −0.336、MidCap −0.711；被清零 15.2%。
  - 100万 2026-07-31：整手前 MidCap −0.400；整手后 −0.934。
  - 100万 2026-08-31：整手前 β −0.100；整手后 −0.280 / −0.313。
- 次要来源：沿用上期造成漂移。60万 2026-07-31 是 step2 失败日，沿用的旧持仓按当日数据算 β +0.222，已超界；这类日子没有逐日披露。
- **v1.2「只披露」的前提被推翻**：漂移不是现金和取整的小噪声，而是系统性的，单方向（低 β、偏离中盘），从 2025-07 以后持续存在。β 是 HARD 约束（Leo 07:56「β·Size HARD」），A 列实际持仓有一部分时间违反 HARD。定级 **P1 实现缺陷**（求解器和整手之间的可交易性不一致）。不定 P0，因为：没有动纸面、live=false、X2 本来就不能用于晋级、求解器本身正确。
- A 列处理：**不作废，但标注**「A_X2 = 违反 HARD β/MidCap 的实际持仓；不能代表冻结策略设计」。冻结后**不调任何参数**（λ、框、slack、单票上限都不动）。修复方式只能由主 Agent 裁定为实现条款（见文末）。
