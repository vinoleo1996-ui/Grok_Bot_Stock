## 1. 动机
原规则按自然月计数；Core 只在月末（及首/末日）调仓，每月最多 1 个调仓日，原规则几乎不可触发。v1.3 100万档出现两段连续整手失败（2026-03→06、2026-08→10-09）未被拦截。

## 2. 规则
- **失败日定义**：某 AUM × 口径的调仓日出现 INFEASIBLE（求解阶段）或 LOT_HARD_FAIL（整手阶段）任一，即为失败日；仅现金 >2%（LOT_CASH_GT2，K2）不算失败。失败日按既定逻辑沿用上期持仓（沿用日），**沿用日本身就是失败日，计入连续段**。
- **新规则（连续）**：同一 AUM × 口径，按该 AUM × 口径的**调仓日序列**（不按自然月），**连续 ≥3 个调仓日**为失败日 → 停跑并上报主 Agent。无数据日（NO_DATA_CARRY）跳过，既不打断也不计入连续段。
- **原规则（②，二选一已定）**：原「单月 ≥2 个 INFEASIBLE 日」**一并扩展**为「单月 ≥2 个失败日」（失败日含 LOT_HARD_FAIL），**同样自 v1.4/Stage2 起生效**；v1.3 及之前运行仍按原文只计 INFEASIBLE。两条规则取并集。
- **恢复**：停跑后须主 Agent **书面裁定**方可恢复；恢复不得改任何 FROZEN 参数。

## 3. 阈值 3 的来历（事实披露，③）
- 起草时**未看任何 v1.3 收益**（v1.3 收益尚未计算，RESIGN 未建）。
- 但阈值 3 是在看过 v1.3 **非收益**失败序列之后定的，不是独立先验：v1.3 各 AUM × 口径最长连续失败段为——100万（两口径相同）4 个调仓日（2026-03-31→06-30）、3 个（2026-08-31→10-09）、2 个（2025-06-30→07-31）；60万（两口径相同）最长 2 个（2020-12-31→2021-01-29）。
- 阈值 3 若追溯适用，会在 100万于 2026-05-29 触发停跑、60万不触发。选 3 而非 2 的理由：2 会把 60万 2020-12→2021-01 这类单次跨年短暂失败也判停；3 = 一个季度的月末调仓，是"持续性失败"的最短合理定义。此理由在看过上述序列后写出，特此披露。

## 4. FWD 中触发后的处理（⑤）
- 触发停跑后，该 AUM × 口径的纸面组合**沿用最后一期持仓继续盯市跟踪**（标记 STOPPED，不再调仓、不再生成新目标），NAV 与披露继续记录，直至主 Agent 书面裁定恢复或终止。
- **不得改任何 FROZEN 参数**（λ、约束、带宽、门槛、调仓日历）来解除停跑。

## 5. 披露
每次运行报：各 AUM × 口径的最长连续失败段（起止日、长度）、失败原因分布、是否触发、沿用日数。
