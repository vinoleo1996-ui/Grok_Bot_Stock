## 3) 三层收益账是否合理

Leo 账：防守 **+1.0～1.5%** + 权益 β **+4.5～5.5%** + AI 纯 α **+8.5～10.5%（已扣 ~1.3% 摩擦）** → 合计 **14.0～17.5%（中枢 ~15.5%）**。

| 层 | Leo 数字 | Arch 评判 | 缺什么证据 |
|---|---|---|---|
| **① 防守垫** | +1.0～1.5% | **偏乐观（危机项）/ 常态偏高估**。20% 仓位若静态持有国债+红利低波：票息/分红贡献粗算约 **0.4～0.8pp** 量级（视 ETF 票息），难到 1.0～1.5。多出来的部分依赖「股灾开关」——把股票仓从 80%→50%、增配国债——这是**择时 α**，不是无条件防守收益。X2 内 510300 MDD −16%，固定 20% 510300 确有同跌问题；但**未**有密封窗上「广度<20% + 波动放大」闸门的 PIT 回测。 | ① 511260/512890/518880 在密封窗+X2 的独立净值；② 宏观闸门预注册（特征、阈值、再平衡、成本）；③ 相对「固定 20% 510300」的 **ΔCAGR/ΔMDD** 消融。 |
| **② 权益池内 β** | +4.5～5.5%（对组合） | **相对 X2 偏保守，相对长熊合理**。组合层若 80%×权益基准：X2 段 C0 510300 CAGR 11.27% → 0.8×11.27≈**9.0pp**（高于 Leo 的 4.5–5.5）；长周期若权益中枢 ~6–7%，则 0.8×≈**4.8–5.6pp**，与 Leo 下沿相近。问题是：方案同时用「HI_LIQ 中大盘市值加权」作 β 锚，与优化器 \(w_b\)=池内流通市值加权 **可对齐**，但 **不能**再隐含另一套「中证500 风格」而不写清。 | 明确报告：权益袖相对 \(w_b\) 与相对 510300 的 β、TE；密封窗 vs X2 分段贡献，避免用单一牛/熊窗定「4.5–5.5」。 |
| **③ AI 纯 α** | +8.5～10.5% 净（扣 1.3% 摩擦） | **明显偏乐观**。纸面 capadv **总** CAGR 仅 13.82%@60万（已含 β+α−成本 1.72%）。若用 X2 的 510300 作粗 β 代理：总收益−0.8×11.27≈**4.8pp** 量级「超额于减仓 β」——远低于 8.5～10.5。即便用长周期 β 4.8pp，则「残差」≈13.82−4.8≈**9pp 毛**，再扣成本后更接近 **7～8pp**，且这还假设优化器/LLM **不损伤**现有 α、并额外加分。B4 总 15.11% 但成本 2.48%、MDD 更深——说明「加事件」历史上换来的是收益与回撤/成本的权衡，不是免费的 +3～5pp 纯 α。 | Core 优化器 vs capadv 的 **密封窗+X2** 并列（未开跑）；Full 事件门卫 vs B4 的独立消融；**禁止**把 LightGBM 样本内 IC 或 LLM 叙事直接换算成年化 α。 |

**加总风险**：三层取上沿再相加 = 典型「叙事相关、样本相关」高估。中枢 15.5% 应降级为 **aspirational band**，正式预期区间建议在证据出现前写作：**「以 capadv 为底（~12–14%），优化器目标先打 Calmar/MDD，再谈是否摸到 15%」**。

## 4) 双引擎 AI：赞同、风险、与分工衔接

### 4.1 引擎一：截面表格学习（LightGBM + Ridge，60% α）

| 项 | 评判 |
|---|---|
| **赞同** | 禁止端到端猜涨跌 ✅；截面排序/IC-Loss ✅；行业+市值正交后的中频特征 ✅；树模型+线性集成抗外推崩坏，方向正确；与「慢残差 α 进优化器」及 Alpha 验收范式（残差/中性化）**同向**。 |
| **风险** | 30–50 特征 + 树模型 → **过拟合 / 多重检验**；若标签用未来 10 日收益，须严格 PIT 与 walk-forward，禁用 X2 调参（与优化器 λ 密封窗纪律一致）；与现有 capacity_adv 特征高度重叠时，**边际 α 可能接近 0**（历史叶失败多因同质量价）。 |
| **分工** | **Alpha** 交付全池慢残差 α 向量（非 Top-25 权重）；**AI** 可提供特征实验，但进 Core 的主 α 须走 Alpha 闸门 / GATE_V3 新口径；**Arch** 审计：禁止名次当 α、禁止用闸门毛收益偷换净收益（内审 P1#4）。 |

### 4.2 引擎二：LLM 公告/预期差（40% α，改造 B4）

| 项 | 评判 |
|---|---|
| **赞同** | 只扫当日触发事件的几十家、JSON Schema（Is_Trash / Catalyst_Score / Surprise_Gap）——比「大模型看 K 线」务实；针对 B4 假增长/忽悠增持的排雷，**问题定义正确**；API 成本叙事合理。 |
| **风险（关键）** | **历史不可严格复现**：模型版本、语料截止、温度与提示词漂移 → 回测不是同一策略；**幻觉**可系统性误标「真超预期」；若语料含未来研报/新闻，有**隐性前视**；把 LLM 分直接当 40% α 权重，与「快因子仅门卫」的已共签工业门道 **可能冲突**（Core 关事件；Full 才开门卫）。 |
| **分工** | **AI** 拥有 Schema、提示词冻结、日更特征落盘；**Data** 保证公告 PIT（ann_date/available_at）；**Alpha** 复核事件腿是否过残差/衰减闸；**Intel** 不替代个股公告，可提供宏观状态供防守闸；**Strategy** 只在 **Full** 接快门卫，**不**进 Core 选参。 |
| **Arch 要求** | LLM 特征必须：① 冻结 prompt+模型 id+温度；② 输出仅三列可审计标量/布尔；③ 历史回放用**当时可得文本**或明确标注「不可回测、仅前瞻纸面」；④ 先做排雷硬过滤，再谈加分；⑤ 与 B4 规则腿做 **who-pays** 预注册，禁静默替换纸面 B4。 |

### 4.3 与「避开伪需求」的对齐

方案明确反对 Transformer/LLM 直接预测股价——**Arch 同意，应写入团队禁令**（与禁 GP、禁端到端 RL 交易并列）。

## 7) 明确反对或降级的点

1. **「每年 100% 刚兑 15%」**——方案正文已否认；Arch **确认反对任何刚兑表述**；对外/对内只允许概率与闸门语言。  
2. **端到端用深度时序/大模型猜涨跌**——反对；与现禁 GP、禁 RL 交易一致。  
3. **用「百亿必须 95% 满仓所以亏钱」反证本方案必达 15%**——容量与仓位灵活性 **成立**，但**不是** α 或 Sharpe 的证据。  
4. **把三层上沿加总写成「预期中枢 15.5%」**——降级为 aspirational；正式预期以跑出的 Core/消融为准。  
5. **Sharpe>1.5 作为当前交付承诺**——记分卡无 Sharpe；先补算现有 capadv/B4/S6 的 Sharpe（日/超额），再设门，否则降级为「研究目标」。  
6. **Core 阶段 60% 表格 + 40% LLM 合成**——与已共签「Core=单慢 α；事件=Full」冲突 → **降级**。  
7. **成本 ≤1.3% 作为 FROZEN 硬门**——现 capadv 1.72%；降级为 stretch，先对齐 B4/capadv 换手量级标定。  
8. **S6 影子成绩外推**——禁止作为晋级或 15% 已验证的证据。  
9. **在 Eng 退市清算落地前，宣称宽池/事件研究「无幸存者问题」**——幸存者审计结论仍有效。
