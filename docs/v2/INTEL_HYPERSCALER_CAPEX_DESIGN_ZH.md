## 0. 一句话假设
云厂商（微软、谷歌、Meta、亚马逊，甲骨文可选）上调资本开支指引，经过 1–3 个季度传导到 A 股供应链公司（光模块、PCB、服务器/液冷、电源、铜连接等）的**订单、业绩预告和季度收入**。市场在指引当天会把“AI 链”整体重定价，但**对单家供应商的敞口和传导时滞**定价不足。可交易的超额来自持有期 20–60 日里，供应商**基本面确认**（业绩预告/季报超预期）之前的那段时间。

## 1. 事件定义与上调/下调的度量

### 1.1 事件
- **事件** = 一家云厂商在财报或电话会上给出或修改**资本开支指引**（年度金额、区间，或定性的增速表述）。数据表：`data/v2/intel_consensus/hyperscaler_capex_guidance.csv`（§10 已补，32 条）。
- 不算事件的：媒体或分析师的预测；没有管理层指引的季度实际 capex（单独记作 `capex_actual`，是辅助变量）；CEO 的定性发言（例如 10-12 Hock Tan 谈“资本约束”，记在 `ai_news_events.csv`，只作情报展示）。

### 1.2 度量（**关键：2024-06 以来没有一次下调**）
已补的 30 条四家云厂商记录里（不含甲骨文）：上调 17（含 1 条定性）、首次给出 7（6 条同比上调、1 条为 MSFT“增速放缓”）、维持 6（含季度指引超预期 1、分析师转述 1），**下调 0**。所以“上调/下调”二分类没有方差，必须用**幅度**来度量：
1. `rev_mid_pct` = (新指引中值 − 前次指引中值) / 前次指引中值。同一财年内的修订；维持 = 0。
2. `new_fy_yoy_pct` = 新财年首次指引中值 / 上一财年实际值 − 1。首次给出时用。
3. `vs_cons_pct` = 新指引中值 / 发布前卖方一致预期 − 1。只有在**有一手可核实的发布前一致预期**时才填（CNBC/Visible Alpha/StreetAccount 引用，带来源），否则为空。这是理想变量，但覆盖不全。
4. **聚合变量（主变量）**：`agg_capex_rev_usd_bn(t)` = 截至 t 日，四家（另一口径含 ORCL）最近一次指引修订的**美元增量之和**，按 90 日滚动窗口汇总。单家事件太稀疏（每家每季 1 次），聚合后更稳。
5. 定性指引（如微软 FY 增速“高于/低于去年”）按 +1/0/−1 打分，**单独一列**，不与金额混算。

### 1.3 方向
主假设只检验“上调幅度越大 → 映射供应商后续越好”。若样本外出现下调，按同一连续变量处理，不另设规则。

## 2. available_at 口径
- 云厂商财报几乎都在**美东 16:00 后**发布（电话会约 16:30–17:30 ET），即北京时间次日 04:00–06:00，**早于** A 股 09:30 开盘。
- 规则：`available_at` = 新闻稿或电话会时间戳（UTC）；**A 股生效日 t1 = 第一个严格晚于美东发布日的 A 股交易日**。比如 10-29（周三）盘后发布 → t1 = 10-30（周四）。
- 为避免与已证伪的“次日效应”重叠，**信号从 t1 收盘后才可用于建仓**，即 t1 收盘出信号、t2 开盘成交。主动放弃 t1 当天的跳空，因为它已被定价（§9 C1/C3 的结论）。
- 美股盘前发布（少见）：若早于北京 21:30，t1 = 下一个 A 股交易日；规则同上。
- 甲骨文财年口径不同（6 月结束），发布时间也在美东盘后，规则同上。

## 3. 供应链映射表：来源、版本与 PIT

### 3.1 只用可核实的公开来源（优先级从高到低）
| 级别 | 来源 | 内容 | PIT 时点 |
|---|---|---|---|
| A | **年报/半年报“前五大客户”**（巨潮资讯网 cninfo 原文 PDF） | 客户名称多为匿名（“客户一”）；部分公司在招股书、问询回复里点名 | 年报**公告日**（不是报告期末） |
| A | **招股书、问询函回复、重大合同公告** | 点名的客户（如“直接或间接供货 Microsoft/Google/Meta/Amazon”）、合同金额 | 公告日 |
| B | **深交所互动易 / 上证 e 互动**的公司回复 | 公司确认或否认对某云厂商供货 | 回复发布时间戳 |
| C | **券商产业链报告**（只用于**提名候选**，不能单独作为映射依据） | 产业链图谱、客户结构估计 | 报告发布日；需 A/B 级来源确认后才能入表 |
| — | 不用 | 自媒体、未署名“产业链调研”、股吧 | — |

### 3.2 映射表结构（`data/v2/intel_supplychain/hyperscaler_supplier_map_vN.csv`，待建）
`ts_code, hyperscaler(MSFT/GOOGL/META/AMZN/ORCL/泛北美云), link_type(光模块/PCB/服务器/液冷/电源/铜连接/芯片), evidence_level(A/B/C), evidence_text, source_url, source_publish_date, valid_from, valid_to, revenue_share_disclosed(若有), map_version`
- **PIT**：`valid_from = source_publish_date`（公告/回复的实际发布日），不是报告期末；`valid_to` = 下一次披露否认或移出之日。信号日只用 `valid_from ≤ t` 的行。
- **版本**：每次补录生成新版 `vN`，不覆盖旧版；回测按信号日选当时有效的行（as-of join），**不用当前版本回填历史**。
- **权重**：A 级 = 1.0，B 级 = 0.6，C 级 = 0（只提名）；若有收入占比披露，则乘以占比。供应商对某云厂商的敞口 `exp_{i,h}` 按此计算。
- 允许“泛北美云”这一类：只能确认“北美大客户”但不能确认是哪一家时，按四家指引修订的平均值映射。

### 3.3 已知风险
前五大客户多为匿名，A 级点名覆盖可能只有几十家，B 级互动易回复会有选择性披露（公司只确认好消息）。设计上接受“窄而准”，不用 C 级扩样本。

## 4. 信号构造
- 供应商 i 在 t 日的暴露：`S_i(t) = Σ_h exp_{i,h}(t) × rev_mid_pct_h(最近一次, t)`，主口径用 90 日窗口内最近一次修订；稳健性用 `agg_capex_rev_usd_bn`。
- **二阶段确认（慢变量核心）**：
  - 阶段 1（预期）：指引上调后，`S_i>0` 的供应商进入观察名单。
  - 阶段 2（确认）：供应商的**业绩预告**（tushare `forecast`，按公告日 PIT）、**快报**（`express`）或**季报收入**（`income`，按 `ann_date`）同比增速超过其自身过去 4 季均值 → 记为“确认”。
- 两个可检验变量：`E1` = 阶段 1 信号（指引后 t2 建仓）；`E2` = 阶段 1 ∧ 阶段 2（确认公告后次日建仓）。**`E2` 是主假设**，因为它就是“慢变量”本身。


### 4.1 业绩确认规则（看结果前固定，主 Agent 冻结条件 0）
- **可用公告类型**（按公告日 `ann_date` 做 PIT，只取 X2 样本内）：
  1. **业绩预告**（tushare `forecast`）：类型为预增、略增、扭亏、续盈之一，且净利润同比变动**下限** `p_change_min` 可得；
  2. **业绩快报**（`express`）：营业收入同比 `yoy_sales`（无则用 营收/上年同期 − 1）；
  3. **定期报告**（`income`）：**单季**营业收入同比（由累计值差分得到单季）。
- **阈值**（三类各自独立判断，满足任一即“确认”）：
  - 预告：`p_change_min` ≥ 该公司前 4 个季度净利润同比增速均值 + 10pp，且 `p_change_min` > 0；
  - 快报 / 季报：单季营收同比 ≥ 该公司前 4 个季度单季营收同比均值 + 10pp，且 > 0；
  - 前 4 季基数不足 3 个可用值 → 该公司该事件不可确认（不补值、不放宽）。
- **确认窗口**：指引事件 t1 之后 **[t1+1, t1+120] 个 A 股交易日**内首次满足阈值的公告；窗口内多条时取**最早**一条。确认日 = 公告日；公告在 15:00 之后或非交易日发布 → 下一交易日；**建仓 = 确认日的下一个交易日开盘**。
- 同一公司对同一云厂商的多个指引事件窗口重叠时，只计最早的未确认事件，不重复计数。
- **有效事件** = 在 X2 样本内满足 E2（映射有效 ∧ 指引上调幅度 > 0 ∧ 窗口内确认）的（公司, 指引事件）对，且建仓日在 HI_LIQ 掩码内。**有效事件少于 30 就停，判为样本不足，不放宽任何条件**（不改阈值、不延长窗口、不降来源等级、不扩股票池）。
- 映射表在冻结共签前不得用于任何收益计算。

## 6. 残差化
每个持有日对收益做截面回归，取残差：
1. 对 **capacity_adv HI_LIQ 信号**（`g1g5_capacity_adv_hiliq_v1_1_daily_weights_*.parquet`）做正交，确保增量不是 capacity_adv 已有的流动性/容量暴露；
2. 对 **风格**（Size、Beta、动量、估值、波动，用项目现有风格口径）做正交；
3. 对 **申万一级行业**哑变量做正交。供应商高度集中在通信/电子，**不做行业正交的话就只是在测“AI 链 β”**。
- 主读：残差收益的 RankIC、多空/多头超额，以及 CMC ΔIC（0.8·z_cap + 0.2·z_new 对比 z_cap），阈值沿用 Alpha §8：ΔIC ≥ +0.003、ΔICIR ≥ +0.05。

## 7. 预注册假设、证伪条件与 who_pays

### 7.1 假设
- **H1（主）**：在 HI_LIQ 内、对 capacity_adv/风格/行业残差化后，`E2`（指引上调 ∧ 供应商基本面确认）在 40 日持有期的多头残差超额，扣 30bp 后 **> 0**，t ≥ 2。
- **H2**：`E2` 的效应 > `E1`。即超额集中在确认之后，而不是指引当天。若 E1 ≥ E2，说明是“标题效应”，与已证伪的次日类结论同源，判失败。
- **H3**：效应随 `exp_{i,h}` 单调，A 级 > B 级 > 泛北美云。

### 7.2 证伪条件（任一成立即判失败，不改规则重测）
1. H1 在 40 日主口径下扣成本后 ≤0，或 |t| < 2；
2. 20/40/60 三档中**两档以上**符号与 H1 相反；
3. 去掉 2024-06 → 2024-12（政策大行情段）后效应消失（符号反转或 t<1）；
4. 残差化前显著、残差化（行业）后消失，判为“AI 链 β”；
5. CMC ΔIC < +0.003，判为对 capacity_adv 无增量；
6. 有效事件数（E2 的股票-事件对）< 30，则不下结论，只记 WATCH。

### 7.3 who_pays
- **对手方**：①按指数/行业 β 交易“AI 链”的资金：指引当天整体买入，不区分单家敞口，持有期内又随情绪整体卖出（例如 10-12 后的去杠杆）；②只在季报公布后才更新预期的卖方/基金，其预期修正滞后于供应商的预告与订单。
- **为什么不会被套利完**：映射需要人工核实（A/B 级来源分散在年报、招股书、互动易），且传导有 1–3 季的时滞，不适合高频资金。
- **何时没人付钱**：若 A 股供应商的预告与订单在指引公布前就已经反映（供应链提前知道订单），则 E2 ≤0，这正是证伪条件 1/2 要抓的情况。
